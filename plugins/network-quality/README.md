# 网络检测与历史报告

Komari >= 1.6.1 的独立插件。通过现有 Agent 远程执行，在服务器上检测全国三网回程、延迟、丢包和流媒体 / AI 服务可用性，把结果保存在自己的 Komari。适配 [pickarm/komari-themes](https://github.com/pickarm/komari-themes) 的节点详情面板；其他主题可继续使用本插件后台。

## 安装与使用

1. 在插件市场添加自用源 `https://raw.githubusercontent.com/pickarm/komari-plugins/main/v1.json`，安装“网络检测与历史报告”。
2. 审阅插件权限并启用。在侧栏打开“网络检测与历史”。
3. 勾选在线 Linux 节点，先“检查运行环境”。需要依赖时，查看结果，再通过“准备缺失依赖”按钮安装。
4. 点击“开始检测”。多个节点会排队执行，任务结束后查看“历史报告”。
5. 定时默认关闭。需要自动更新时，在“定时任务”中选择节点、设置每天 / 每周 / 五段 Cron 并启用。所有时间均为北京时间。

安装插件、刷新页面和公开访客访问都不会自动启动检测。切换到新主题之前，可以先使用本插件后台独立验证结果。

## 线路变化提醒（1.1.0）

每次检测完成后，把当前成功取得的线路名称，与同节点、同省份、同运营商、同地址族、同包型的上一次有效成功采样比较，并将变化写入当前报告。顶部突出提示数量，明细展示原线路 → 新线路和对比时间；Junimo 庄园 >=2.2.0 还会突出标记前台省份单元格。这里比较的是 TcpQuality 返回的线路名称，不是完整逐跳路径。

失败、无响应、未知线路、缺测、另一节点/地址族/包型、已知不同 TcpQuality 版本不作为可比线路，空格、字母大小写和目标 IP 的变化也不会单独触发。部分失败时按目标向前查找最近成功样本。首次或缺少可比历史会建立基线，不报告变线；原报告缺少字段时保持兼容。对比信息和原报告一起持久保存，即使旧基线被保留策略清理，仍可查看当时的变化。公开接口继续隐藏完整 IP、原始输出及隐藏节点，访问页面不会启动检测。

## 默认设置与自定义

| 设置 | 默认值 |
| --- | --- |
| 检测模块 | 三网回程、解锁 |
| 地址族 | IPv4，可切换 IPv6 / 双栈 |
| 省份 | 全国 31 省三网，可选择子集 |
| 每目标探测次数 | 30，可设置 1–600 |
| 节点内探测并发 | 4，可设置 1–31 |
| 同时运行节点数 | 1，避免重叠测量 |
| 单任务最长时间 | 30 分钟，可缩短 |
| 历史保留 | 90 天、每节点最多 100 份，可调整 |
| 自动定时 | 关闭，由管理员按节点开启 |
| 公开摘要 | 开启，过滤完整 IP 和原始输出 |

每节点不可重复排队。进程重启后会继续回收已创建的 Komari 任务；下发结果不确定时不会自动再跑一遍。错过的定时任务不集中补跑。新检测失败时，前台默认继续显示之前的成功或部分成功结果。

## 检测范围

- **回程**：从目标服务器向国内三网检测，表格显示省份、运营商、线路、往返延迟、丢包和有效样本。线路名称由上游识别，不把推测标成确定事实。
- **解锁**：使用 IPQuality 检测 TikTok、Disney+、Netflix、YouTube、PrimeVideo、Reddit、ChatGPT 等上游支持的项目。状态分为可用、受限、未能确认和不支持；超时不等于被封锁。实际服务项目随固定引擎版本列示。
- **真实去程**：首版不提供“国内节点 → 目标服务器”的逐跳检测，不把回程倒序冒充去程。
- 不做硬件压测、带宽测速或 rootfs 测评；本地报告不上传到 NodeQuality / TcpQuality 报告站。检测本身仍会访问目标服务、测试节点、公开数据接口和工具下载源。

## 环境要求

支持具有 Bash 4+ 的 Linux；三网探测需要 root 和 `CAP_NET_RAW`。LXC 的 root 也可能缺少该能力，环境检查会明确提示。IPv6 需要服务器具有可用 IPv6 网络。禁用了 Agent 远程执行的节点无法运行检测。

“准备缺失依赖”目前支持 Debian / Ubuntu 的 apt 和 Alpine 的 apk，使用系统官方软件源安装 Bash、curl、jq、探测和 DNS 工具等必要依赖。其他发行版可按照环境检查提示手动准备；插件不会自动创建 swap、启动容器或下载 BenchOS。环境不满足时展示缺失项，不伪装成 100% 丢包。

## 数据与公开边界

插件保存目录为 Komari 管理的 `data/plugin-data/network-quality/`。请将其纳入主机备份；升级插件保留，删除插件时 Komari 可能删除此目录。Komari 核心远程任务有自己的清理周期，本插件会另存报告和原始输出。

访客只有只读摘要接口；后台启动、配置、任务队列、完整历史和原始输出仅管理员可访问。隐藏节点不会出现在公开接口。原始内容按纯文本展示和下载，不执行输出中的 HTML。

## 接口

根路径：`/api/plugins/network-quality/v1`。所有响应为 JSON，`raw` 除外。

- `GET public?uuid=<节点>&report_id=<可选历史ID>`：版本 1 的公开脱敏报告和历史索引；缺失 / 隐藏节点返回 404。`enabled:false` 表示插件或公开展示关闭。
- `GET context`、`GET jobs`、`GET history?uuid=...`：管理员读取配置、节点、队列、结构化报告。
- `POST start`：`{uuids:[...],mode:"detect"|"preflight"|"prepare",options?:{...}}`。
- `POST config`：`{config:{...}}`，提交完整配置；字段见 `src/types.ts`。
- `GET raw?uuid=...&report_id=...`：管理员下载原始输出。

POST 要求管理员会话、同源请求、`Content-Type: application/json` 和 `X-Network-Quality: 1`，不接受任意命令。

## 开发与发布

```sh
npm ci
npm run typecheck
npm test
npm run check
npm run build
npm run pack
```

版本标签为 `network-quality-v1.0.1`。发布工作流在测试后上传安装包。`vendor/` 保留已固定引擎的源码、许可证与来源，具体 commit 和 SHA-256 见 `src/runner.ts` 和 `THIRD_PARTY.md`。

当前自动化测试使用格式样例和模拟 Komari 任务，不代表所有实际 VPS / 网络已完成实机验证。正式使用前，建议先选择一台服务器检查环境并手动检测。
